**多设备 + 厂商 GUI/SDK**，没有一体机 `POLARITY:*` 命令树。- 同目录 Final Plan 已写死：极性不是一条 SCPI，且排除 PTM；与 coded driver 的「单 TCP 一体机」假设直接冲突。- `SCPI_PROTOCOL.md` 自身也承认该协议是 assumed integration contract。- **结论：不能拿这套驱动对照新资料做协议正确性验收；它最多是开发期模拟器契约，量产无效。**### 2. `UDL.SantecPTM` — 相对 PTM 手册大体正确；相对公司 RD-SP 基线则产品选错- 与 [PTMScpiCommands.h](TestEquipmentDrivers/UDL.SantecPTM/PTMScpiCommands.h) / 手册 Table 8 已正确标「暂定」）。- 新 PDF **未提及 PTM**；公司 Final Plan **明确排除 PTM-100**。官网 Cable Assembly 虽支持 PTM，那是另一条硬件 BOM。- **结论：作为「独立 PTM 驱动」交叉验证通过（除结果解析待真机）；作为「公司当前极性产线 UDL」则不匹配供应商刚给的 XNS/RD-SP 资料包。**### 3. 供应商 `doc/` 安装包 — 不改变协议结论- 含 XNS 03.126 / Cable Assembly 1.14.13 / NI-VISA（与官网版本一致量级）；PDF 示例偏旧（03.97 / 1.12.x）。- **不要安装 exe** 也能得出结论：这是产线软件交付物，不是 SCPI 手册；无法从中推导 `POLARITY:*` 或替代 PTM 手册。## 总判定- **验收对象 = 公司已定料号 RLM-100 + OSX-100 + RD-SP-100-SM**：现有 `POLARITY:*` 驱动是错误路径；`UDL.SantecPTM` 也不能替代；正确方向是 Final Plan 的多设备编排 + RD-SP Mapping SDK（第一版不直接写 XNS）。新 PDF 强化了这一结论。- **若将来另采购独立 PTM**：`UDL.SantecPTM` 命令侧可继续用，优先用真机 `SendCommand`/`GetRawResult` 锁定 `TEST:RESult?` 格式后再定解析器。## 建议后续（确认本结论后可选执行）1. **冻结** `SantecPolarity` 的 `POLARITY:*` 为模拟器/教学 stub，README 显著标注「非真机协议」。2. 以 Final Plan 为准推进真正的 `UDL.SantecPolarity`（复用已有 `UDL.SantecRLM` / `UDL.SantecOSX`，补 RD-SP SDK/Worker）。3. 保留 `UDL.SantecPTM` 仅当 BOM 含 PTM；否则勿并入产线验收。4. 真机联调前向供应商再要：**RD-SP 官方 SDK/API**（或明确是否只允许经 Cable Assembly/XNS API）——新 PDF 仍不提供可编程 SCPI。## 本次刻意未做-
